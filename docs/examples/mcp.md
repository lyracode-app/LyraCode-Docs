# 连接 HTTP MCP 服务

目标：添加一个真实 HTTP MCP 端点，获取工具并完成只读调用。此示例提供配置形状，不提供可访问的服务器；`mcp.example.com` 与令牌均为占位值。

无鉴权的服务可去掉 Authorization Header。仅当服务实际使用该传输时才保留 `streamableHttp`；旧 SSE 端点需选择对应传输，协议版本也应与服务协商，不能随意复制版本号。

## 导入与调用

1. 在 MCP 设置中新建配置，把修改后的 JSON 放入配置编辑入口。
2. 检查解析后的名称、URL、传输和鉴权，启用并连接。
3. 获取工具列表，挑选一个无副作用工具，查看它的输入 schema。
4. 在对话中要求调用该工具，只提供 schema 要求的参数。
5. 检查结果是否来自预期服务器，字段和值是否正确。

**成功标志：** 连接可用、列表包含目标工具、实际调用返回有效业务结果。仅返回 HTTP 200 不足以证明 MCP 会话或业务成功。

## 配置限制与排障

- 每份 `mcpServers` 中恰好一个服务器，多个端点分别添加。
- 接受 HTTP(S) URL，`command`/`args` 的 stdio 配置不能直接用于这个入口。
- Header 值为字符串；同时填写 `url` 与 `baseUrl` 时两者必须相同。
- 401/403 先查鉴权；404 查端点路径；握手/解析失败查传输与协议版本。
- 配置含密钥，分享之前改回占位符。服务不可达时不能通过换成示例域名验证。

解析与连接实现见[扩展机制](/developer/extensions)。
