# 配置模型与服务商

目标：建立可用的模型连接，并根据任务选择文本、工具调用、视觉等能力。准备好服务商给出的接口地址、API Key 和模型 ID。

## 添加配置

需要同步梦汐 API 平台的 Key 与模型列表时，看[第三方账号](/manual/accounts)；手动配置服务商可直接继续以下步骤。

1. 在设置的模型/服务商管理中添加配置，给它起一个可辨认的名称。
2. 选择匹配的协议。应用包含 OpenAI 兼容接口、Anthropic 和 Gemini 请求路径；兼容接口也可能区分 Chat Completions 与 Responses。
3. 按对应配置页提示填写基础地址。不要把不同协议的完整请求路径互相套用，也不要重复添加 `/v1` 等路径段。
4. 填入密钥，获取模型列表或手动填写服务端支持的精确模型 ID。
5. 在对话选择此配置和模型，先验证文本回复，再验证一次只读工具调用。

**成功标志：** 对话正常返回，工具测试能读取工作区目录；如需视觉，再单独验证一张无敏感信息的图片。

## 能力与分工

| 任务 | 所需能力 | 验证方法 |
| --- | --- | --- |
| 普通问答 | 文本生成 | 简短回复 |
| 修改项目 | 工具调用 | 列目录、读取文件，再进行小范围修改 |
| 理解截图 | 视觉输入或已配置的视觉补充模型 | 描述测试图片中可核对的内容 |
| 设备图片识别 | 可用的视觉模型及设备能力 | 先检查设备能力，再验证当前截图 |
| 子代理任务 | 已启用编排及有效的子代理模型配置 | 从独立的只读子任务开始 |

界面的能力开关不会给服务端增加能力。模型 ID 存在也不保证支持工具、图片、推理参数或长上下文。

## 高级参数如何调整

先保持默认参数；连接和基础任务通过后，再逐项修改温度、输出上限、上下文或推理深度。自定义请求 Header/JSON 应以服务端接受的字段为准，每次只改一个变量。输出上限过小可能截断回答或工具参数；更大的上下文也不保证服务端接受。

纯提示模式会影响工具提供。需要 Agent 实际执行任务时，检查此模式及 Agent 工具设置。联网搜索也有自己的设置和后端，不能从模型可用推断搜索可用。

## 常见失败

| 现象 | 优先检查 |
| --- | --- |
| 401/403 | 密钥、账号权限、服务商限制 |
| 404 或模型不存在 | 地址拼接、协议、精确模型 ID |
| 400 或不支持的字段 | 自定义请求、能力开关、推理/输出参数 |
| 429 | 服务商额度与限速，避免连续重复请求 |
| 文字正常但工具失败 | 工具调用能力、纯提示模式、工具开关及参数记录 |

保留脱敏后的错误、协议和模型 ID 可帮助定位；完整 API Key 不应出现在反馈中。实现入口见[服务商适配](/developer/providers)。
