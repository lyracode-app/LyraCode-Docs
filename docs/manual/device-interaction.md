# 设备交互与桌宠

目标：从悬浮对话发起设备任务，并根据实际能力确认操作结果。

## 启用设备交互

1. 在“设置 > 设备交互”中启用功能，并按提示授权无障碍服务和悬浮显示。
2. 如需 Shell 能力，连接并授权相应服务；图片识别需要可用的视觉模型。
3. 从悬浮对话提出一个简单任务，例如检查当前页面，不进行修改。
4. 让 Agent 先调用 `device_get_capabilities`，核对实际连接状态与权限，再执行任务。
5. 检查工具结果和操作后的界面。发出了点击或命令，不表示目标操作已经成功。

无障碍、Shizuku Shell、Root 和视觉模型各自提供不同能力；打开设备交互总开关不会自动授予全部能力。

## 普通模式与完全权限

“设备交互完全权限”默认关闭。开启时需要通过 Android 锁屏凭据或生物验证；未设置安全锁屏凭据的设备不能开启。开启后可操作任意应用并执行敏感操作，普通模式的重复确认会减少，应在理解范围后使用。

验证信息由系统处理，Lyra Code 不读取或保存。该授权不会随备份或设备迁移恢复；也不会自动授予 Shell、Root 或其他系统权限。关闭后恢复普通模式限制。

## 使用桌宠

桌宠提供悬浮入口与任务状态反馈。长按桌宠进入设置，可调整大小、吸边、透明度和声音，并导入、切换或导出宠物包。

API 2 包使用 ZIP 分发，包含 `manifest.json`、入口 JavaScript 和可选配置/资源。导入会加入桌宠库并切换，已有样式保留；移除当前样式会回到默认样式。个人参数与导出源码分开保存。

如果导入后显示备用图标，可能是脚本语法或生命周期错误；长按仍可进入设置。想自定义外观，可从[完整 API 2 示例](/examples/pet)开始。

## 无响应时

先检查无障碍是否仍连接、悬浮权限、实际 Shell 能力和模型请求错误。截图/文本可能来自瞬时状态，页面变化后应重新获取，避免依据旧坐标反复操作。更多诊断见[问题排查](/reference/troubleshooting)。
