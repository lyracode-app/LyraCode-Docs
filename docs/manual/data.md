# 备份与迁移

目标：在换设备、更新或调整环境前保存可恢复的数据，并知道备份未覆盖什么。

## 导出备份

1. 在设置中的备份入口选择导出内容，例如配置、会话、提示、记忆、Skills 和各类服务配置。
2. 明确是否包含密钥。默认不包含；包含后 ZIP 可能保存 API Key、密码等凭据，应按敏感文件保管。
3. 导出到本地或配置的 WebDAV，确认文件存在、大小合理，并保存一份独立副本。
4. 在不影响当前数据的环境中验证恢复，或至少检查备份清单与所选内容。

只看到“导出成功”仍不足以证明你所需的全部数据都在包中。

## 哪些内容需要另外保存

| 数据 | 处理方式 |
| --- | --- |
| 应用设置、会话、Skills 等 | 以导出勾选项目及备份清单为准 |
| API Key 与远程密码 | 仅在明确选择包含密钥时导出，恢复后重新验证 |
| 工作区项目和其他共享文件 | 单独复制或使用项目版本控制；不要假定已进入应用备份 |
| Linux rootfs、安装的软件和内部项目 | 另行保存重要项目与环境重建信息；普通备份不包含完整 rootfs |
| Android 权限与完全权限授权 | 在目标设备重新授予，不能依赖备份恢复 |
| 第三方账号登录态 | 不纳入备份或设备迁移；目标设备重新登录 |

## 恢复与迁移

恢复前先备份目标设备现有数据。选择应用提供的合并/覆盖模式，理解冲突处理后导入。恢复完成后逐项验证模型、服务连接、Skills、工作区目录授权和任务配置。

卸载、清除数据和删除 Linux 环境都会影响应用私有文件；在做这些操作前，必须已保存其中的项目与必要数据。

## 日志、统计与诊断入口

请求记录见[日志](/manual/logs)，Token 口径与模型排行见[统计](/manual/statistics)，平台余额与登录状态见[第三方账号](/manual/accounts)。这些功能分别提供独立入口，迁移后逐项核对。

设备诊断可提供系统、架构、内存和存储信息，用于排障；不要把诊断结果当作设备真伪的唯一证明。公开问题报告前，移除密钥、私人对话和真实远程地址，见[排障信息清单](/reference/troubleshooting)。
