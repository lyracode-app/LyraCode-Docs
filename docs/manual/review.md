# 工具审批与变更审查

AI 的完成说明、工具执行记录与实际产物应相互对应。审查时先看目标和参数，再看真实结果。

## 执行前的审批

核对工具名称、文件路径、命令、目标服务和本轮范围。拒绝时可说明应如何调整。会话自动批准会改变普通对话后续审批方式，启用前确认当前任务范围；[设备完全权限](/manual/device-interaction)与[MCP 服务端](/manual/mcp-server)各有独立行为。

## 执行后的结果

### 命令

检查退出码、stdout 和 stderr。后台命令需要继续查看返回的输出路径、进程和端口；“已启动”不等于服务健康。

### 文件

展开文件变更卡片，逐项核对路径、增删行和 Diff，再读回重要片段。卡片展示最近一组变更，不替代完整 Git 差异。隐藏卡片也不会撤销写入。

## 手动编辑冲突

AI 读取后文件可能已被用户或其他任务修改。遇到匹配失败或内容冲突，先保留自己的修改，重新读取最新内容，再做精确替换。不要通过连续整文件覆盖来解决冲突。

## 验收示例

让 AI 修复按钮时，核对只改了相关文件，再运行项目已有检查并实际点击页面。测试不可用时记录原因，以及哪些行为仍需验证。TODO 标成完成或回复“已修复”本身不构成验证。

工具输出字段见[参数参考](/reference/tools)，审计排查见[日志](/manual/logs)。
