# 附件与上下文压缩

附件、工作区引用与历史摘要共同影响模型看到的内容，但各自有不同来源和更新方式。

## 添加附件

### 上传文件与图片

在输入区添加文件或图片，发送前核对附件列表并说明读取目的。图片可按界面流程使用原图或裁剪；图片理解要求模型本身或已配置的视觉补充能力。

上传文本文件不等于授权整个所在目录；要让 AI 编辑项目，请[选择工作区](/manual/workspaces)。移除尚未发送的附件后，再核对本轮列表。

### 引用工作区文件

选择当前工作区后，可在输入区通过 `@` 触发文件选择，搜索并选中需要引用的文件。确认路径属于当前项目，发送后检查读取结果。工作区切换后重新选择引用，避免沿用其他项目的上下文。

## 查看与压缩历史

长任务可以手动压缩历史，也可按设置中的轮数或 Token 阈值自动压缩。压缩使用摘要替代部分后续请求上下文，不会把项目文件改写成摘要。

### 压缩前

确认压缩模型可用，保留关键路径、未完成工作、禁止事项和验收条件。大量附件或工具输出仍可能占用上下文，摘要不能代替读取当前文件。

### 压缩后

核对当前上下文信息，继续时重申关键约束，并让 AI 先检查最新文件。若摘要遗漏细节，补充必要片段；若任务目标已完全不同，新建对话通常更清晰。

## 常见问题

图片无法识别时检查视觉配置；文件未找到时检查工作区和相对路径；上下文仍很大时检查附件、工具输出与摘要是否生效。富媒体展示见[外观与内容显示](/manual/customization)，压缩实现见[协议适配](/developer/providers)。
