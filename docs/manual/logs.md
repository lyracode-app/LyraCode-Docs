# 日志与请求排查

从侧菜单栏打开“日志”，查看应用保存的审计记录。它适合定位模型请求、工具调用和错误；服务进程自己的 stdout/stderr、静态服务器请求日志需在相应入口检查。

## 查找一条记录

1. 记下失败时间、模型和操作，再进入日志页刷新。
2. 用类型标签缩小范围，输入关键词搜索。
3. 打开记录查看详情；较早记录可通过“加载更多”继续查找。

切换类型或搜索会重新载入列表。排查刚发生的问题时先刷新，避免把旧错误当成当前结果。

## 如何阅读详情

### 模型请求

核对服务商、模型、目标地址、HTTP 状态和错误体。认证错误先查 Key，路径错误先查基础 URL 与请求路径，工具调用失败再查参数和返回内容。不要因 HTTP 成功就断定整轮任务成功。

### 工具与执行

区分“模型提出调用”“审批通过”“工具执行完成”。命令检查退出码和 stderr；文件操作检查真实目标与 Diff。涉及后台任务时继续检查[输出和服务状态](/manual/automation)。

## 示例：对话报错后

按本次时间筛选相关类型，搜索模型名或错误关键词，打开详情保存脱敏错误码。回到设置修正一项后，以小请求重试，再检查新的记录，避免一次改动多个配置导致原因不明。

## 删除与反馈

可删除单条记录，或清空日志，均需确认。清理前保留排障需要的信息；删除日志不会撤销已经执行的操作。

公开反馈时移除 Authorization、Cookie、API Key、私人消息及真实服务地址。说明复现步骤、版本、时间和脱敏错误，见[问题排查](/reference/troubleshooting)。用量口径见[统计](/manual/statistics)。
