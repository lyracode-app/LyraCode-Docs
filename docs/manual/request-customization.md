# 自定义模型请求

目标：为某个模型追加或覆盖请求 Header 与 Body 字段，处理网关校验、代理要求或非标准服务商的兼容问题。基础配置见[配置模型与服务商](/manual/models)。

## 入口与适用范围

1. 打开「设置 → 模型与服务商」，选中要调整的配置。
2. 进入该配置的编辑页，点右上角「自定义」。
3. 在「模型请求自定义」页顶部的下拉框选择已启用的模型。

配置内没有已启用模型时页面提示先启用模型。使用账户凭据的服务（ChatGPT 与 DeepSeek Harness）不显示这个入口：它们的请求结构由授权方式固定，不接受覆盖。

设置按「配置 + 模型」分别保存。同一配置里换一个模型，就是另一份独立的覆盖设置。

## 预览显示什么

页面展示最近一次请求的原生字段结构；还没有发出过请求时展示该协议的默认结构。

- 消息、提示词与工具内容以空值占位，不显示真实对话内容。
- 未修改的字段仍由应用在发送时动态生成，包括历史消息、工具定义和上下文。
- 覆盖只影响列出的字段，不会冻结整份请求。

三种协议的默认结构不同，例如 OpenAI 兼容使用 `Authorization: Bearer {{apiKey}}`，Anthropic 使用 `x-api-key` 与 `anthropic-version`，Gemini 使用 `x-goog-api-key`。以页面实际显示为准。

## 追加与覆盖 Header

1. 点「添加 Header」，填写名称与值。
2. 保存后立即作用于该模型的下一次请求。

规则：

- 名称必须非空，且在同一模型内唯一；只比较大小写不同的名称也算重复，保存会失败。
- 与已有 Header 同名（忽略大小写）时覆盖其值，不会重复发送两份。
- 修改已有 Header 的名称等于删除旧名称并新增一条，两者都写入本次保存。
- 删除内置 Header 会先弹出确认，保存配置后生效。

值中可以使用 `{{apiKey}}`，它会被替换成该服务商当前的 API Key。需要把密钥放进自定义 Header 时优先用它，避免把明文写进配置。

## 追加与覆盖 Body 字段

1. 点「添加 Body 字段」，填写 Key 与 JSON 值。
2. 值按 JSON 解析：字符串要带引号，数字、布尔和对象按 JSON 语法书写。

规则：

- Key 必须非空且唯一，不允许空值。
- 与请求中已有的顶层字段同名时覆盖其值。
- 删除内置 Body 字段同样先确认、保存后生效。
- 值末尾不允许出现额外内容，解析失败时保存被拒绝并提示检查字段与 JSON。

嵌套对象整体写入即可，例如为某个网关补 `{"provider":{"order":["deepseek"]}}`。

## 回传历史思考内容

「回传历史思考内容」默认开启。关闭后，历史消息中的 `reasoning_content`、`thinking`、`reasoning_details` 等字段以及 Responses 输入里的 `reasoning` 项不再回传给服务端。

关闭可以减小请求体积，也可能让需要连续推理的模型失去上一轮思路。遇到服务端拒绝这些字段或请求体过大时，先只改这一个开关，再看效果。

## 保存、切换与恢复

- 改动会在切换模型时提示先保存；未保存的修改不会生效。
- 「保存当前模型配置」只提交当前模型。
- 「恢复当前模型默认设置」清除该模型的全部覆盖，并恢复回传思考内容的默认值。

**成功标志：** 保存后发出的请求带上新增字段，服务端不再返回对应的字段错误，且其他模型的请求没有变化。

## 数据与备份

覆盖设置属于模型配置的一部分。Header 值若写入明文密钥，会随模型配置进入应用备份，即使备份没有勾选包含密钥。因此长期使用应改为 `{{apiKey}}`。

请求排错时先看[日志与请求排查](/manual/logs)：HTTP 审计导出不会包含账户凭据服务的请求，普通服务商的 Header 也会按审计规则脱敏。

## 常见问题

- **保存提示检查字段：** 名称重复、名称为空或 JSON 值不合法，逐项核对后重试。
- **改了但请求没变：** 确认已保存、选中的是同一个模型，并检查该字段是否被应用在发送时重新生成。
- **400 报未知字段：** 服务端不接受该字段，删除后重试；不要靠反复添加近似字段试探。
- **401 或 403：** 检查自定义 Header 是否覆盖了原本的认证头，或 `{{apiKey}}` 对应的密钥是否有效。
- **看不到「自定义」入口：** 当前配置使用账户凭据，或还没有已启用模型。
