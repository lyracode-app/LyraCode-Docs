# 定时与后台任务

目标：区分会话进度、持续运行的进程与按时间触发的任务，并知道如何确认结果。

| 类型 | 作用 | 去哪里验证 |
| --- | --- | --- |
| 对话 TODO | 展示多步骤任务进度 | 对话中的步骤及最终产物 |
| 下载任务 | 跟踪文件下载与错误 | 下载状态、目标文件与可选校验值 |
| 后台命令 | 启动服务器、watcher 等持续进程 | 输出文件、进程、端口与实际服务 |
| 定时任务 | 在计划时间创建并运行任务 | 任务页的下次运行、状态、结果和错误 |

## 创建定时任务

1. 打开任务页面创建任务，写清目标及允许访问的服务或数据。
2. 选择一次性、每天、每周或每月等页面提供的计划，填写时间并核对设备时区。
3. 选择有效的模型配置与模型，保存并启用。
4. 核对“下次运行”时间。先用一个近期、只读的小任务验证配置。
5. 运行后检查最后运行时间、结果和错误；停用或删除不再需要的任务。

可先用提示语“报告当前设备时间与时区，不修改文件、不调用外部服务”验证调度。成功标志是任务页产生本次运行记录和结果，不能只看启用开关。

## 执行限制

定时任务通过 Android WorkManager 调度。省电、网络、后台限制和系统调度会影响实际执行时间；它不是精确到秒的闹钟。设备时区改变后应重新核对下一次时间，避免将自然语言中的“明天”永久写成含糊规则。

依赖交互确认的操作不适合无人值守任务。尤其是发送邮件等需要前台确认的操作，不能通过后台执行跳过。模型或服务凭据变化后应重新验证任务。

## 管理后台进程

让命令工具使用 `background=true`，记录返回的输出路径，然后单独检查启动日志和健康状态。再次启动前先确认旧服务是否仍占用端口。停止时针对实际进程或环境执行，并再次检查端口。

PRoot 禁用/删除环境会关闭该环境保留的进程；强制停止应用或系统回收进程也会影响服务。对话停止按钮不应被当成所有后台任务的停止开关。
