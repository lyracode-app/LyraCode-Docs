# 子代理协作

子代理把相互独立的分析或修改分给多个模型任务，结果由主任务汇总。它与复制聊天历史的[对话分支](/manual/conversation-branches)不同。

## 配置与开启

在设置中配置并启用子代理编排，为候选子代理选择有效服务商和模型。仅启用开关但没有可用候选模型，任务无法分派。先用只读代码检查验证连接与结果。

## 拆分任务

### 只读任务

适合分别检查界面逻辑、数据流和测试覆盖。给出具体问题、允许读取的目录和预期输出，避免多个任务重复分析同一问题。

### 允许写入的任务

子任务需明确写入路径，避免重叠。只读任务不能同时声明写入范围；允许写入的任务不能省略范围。共享文件或公共接口应由主任务协调。

## 一个任务示例

> 请让子代理分别只读检查 UI 事件处理和数据持久化，报告具体文件与原因。由主任务汇总后实施必要修改，并运行相关检查。

主任务应核对报告与真实代码，再审查最终 Diff。子代理返回成功不保证所有文件已经保存或测试通过。

## 限制与排障

子代理不能递归再分派子代理。无法使用时检查总开关、候选模型、工具开关和路径范围；并发写入冲突时重新读取当前文件。额外模型调用会影响[用量](/manual/statistics)，实现见[工具接入](/developer/agent-tools)。
