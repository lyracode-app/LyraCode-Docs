## 6. 文件操作与代码编辑最佳实践

### 6.0 先懂：AI 是怎么"改文件"的？

AI 改文件**不是**整篇重写，而是像医生做手术一样**精准下刀**：

1. **先读**：AI 先读取文件内容，看清现状；
2. **定位**：确定要改哪一段（"第 30 到 40 行"或"某个唯一文本片段"）；
3. **替换**：只替换目标段落，其余原封不动；
4. **备份**：覆盖修改前，自动在**同目录**生成 `.bak` 备份；
5. **报告**：把改动对比（diff）展示给你看。

所以你可以放心：**AI 不会"顺手"改掉你没让它动的地方**——除非你让它整体重写。

### 6.1 四条编辑铁律

1. **先读后改**：AI 动工前必须读相关文件、README、构建脚本——你也一样，改代码前先让 AI「读一下这个文件」；
2. **小步精确**：能改 3 行就不要改 30 行，能精确匹配就不要模糊重写；
3. **复用约定**：沿用项目已有的风格、函数、命令，不臆造新依赖；
4. **验证收尾**：改完必须跑相关测试/构建，**确认成功才算完**，不能改完就丢给你。

::: tip 你可以这样要求 AI
「先读 README 和 main.py，然后按项目风格修改，改完跑一下测试，最后把结果汇报给我。」
:::

### 6.2 编辑工具选型：什么时候用哪个？

| 场景 | 工具 | 关键点 |
| --- | --- | --- |
| **新建文件** | write_file | 整个文件全新写入 |
| **精确替换一小段** | edit_file | 旧内容必须唯一；匹配不到/不唯一会拒绝 |
| **替换一大段（按行号）** | edit_file(start_line/end_line) | 适合 30 行以上的大改动 |
| **在文件末尾加内容** | append_file | 比如往日志/清单追加一行 |
| **移动/重命名** | rename_move | 工作区内 |
| **删除** | delete_file_or_folder | 只删文件或**空**目录 |
| **读大文件** | read_file_lines | 先读片段再定位，不整篇加载 |

> 新手不用记工具名——**用嘴说就行**：「帮我新建一个 `notes.md`」「把第三行改成 xxx」「在文件末尾加一句」。AI 会自己选对工具。

### 6.3 内容搜索技巧（搜"文件里写了什么"）

`search_files` 只能按**文件名**找，想按**内容**搜要用命令。常用：

```bash
# 在项目里搜所有含 TODO 的 .kt 文件（首选，快）
rg -n "TODO|FIXME" --glob '*.kt'

# 如果没有 rg，用 grep 兜底
grep -rn "TODO" --include='*.kt' .

# 只想看每行命中几次/只看前 50 行，防止刷屏
rg -c "pattern" . | head -50
```

你不需要背命令——**直接说**：「帮我在工作区里搜所有含 `password` 的文件」，AI 会执行并汇报。

### 6.4 修改回滚：你的"后悔药"

- **.bak 自动备份**：AI 覆盖修改前，会在同目录生成 `xxx.bak`。比如你让 AI 改 `main.kt`，会留下 `main.kt.bak`（改之前的版本）；
- **恢复方法**：发现改坏了，直接对 AI 说「把 main.kt 恢复成 main.kt.bak 的内容」；
- **编辑器的未保存修改**：退出编辑器时会提示你保存；
- **重要文件双重保险**：对特别重要的文件，先让 AI 手动复制一份：`cp 文件 文件.bak`。

### 6.5 项目指令文件（AGENTS.md）：给 AI 立规矩

在每个项目的根目录放一个 `AGENTS.md`（或 `AGENT.md`），AI 动工前**会自动读取并遵守**。示例：

```markdown
# 项目约定
- 构建命令：./gradlew assembleDebug
- 测试命令：./gradlew test
- 风格：Kotlin，2 空格缩进，禁止魔法数字
- 涉及 secrets 的操作一律拒绝
```

- 指令按目录层级生效：**深层目录的规则覆盖浅层**；
- 但**永远不能覆盖**你的直接要求和基础安全规则（比如不能写"绕过审批"这种指令，写了也无效）。

## 7. 命令执行：Termux / Shizuku / Root

### 7.0 三条通道，三种权限（回顾）

还记得第 1 章吗？命令不是 AI 直接跑的，而是通过三个"通道"之一：

| 通道 | 身份 | 能干什么 | 需要 |
| --- | --- | --- | --- |
| **Termux** | 普通应用用户 | 构建、Git、脚本、装软件、搜内容 | 装 Termux 并授权（第 1 章 5 节） |
| **Shizuku** | ADB 级别权限 | 系统命令（pm / dumpsys）、受保护路径 | 装 Shizuku 并激活 |
| **Root** | 手机最高权限 | 系统文件、/data、系统包管理 | 手机已 root |

::: warning 权限纪律（最重要的一条）
**能用低权限解决的，绝不升级权限。** 普通任务用 Termux 就够了。Shizuku/Root 只在真正需要系统级操作时才配置和使用。
:::

### 7.1 run_command（Termux 通道）使用要点

- **默认目录**：命令默认在你选定的工作区里执行，**不需要**先 `cd`；
- **跨目录**：用 `workDir` 参数指定，或写绝对路径；
- **多行命令**：告诉 AI 用多行数组传参（比如写脚本）；
- **串联步骤**：AI 会用 `&&` 把"前一步成功才继续"的命令连起来；
- **交互式程序别跑**：`vim`、`top`、游戏这类需要持续按键的程序不能跑；
- **长驻服务**：开发服务器这类要一直运行的，用后台模式（AI 会拿到进程 ID 和日志文件）——**但启动成功≠服务健康**，要另外检查进程和日志；
- **超时**：命令最长 600 秒；输出太长时先存到文件再读：`命令 > out.txt 2>&1`；
- **高危拦截**：`rm -rf /`、写系统设备等命令会被 App 拦截——但**你仍然要自己审查**，AI 不是绝对可靠。

### 7.2 安全命令示例（看懂这些你就入门了）

```bash
# 想删东西？先列出确认，再决定删不删
find . -name '*.tmp' -type f

# 看看哪个文件夹最占空间
du -sh * | sort -h | tail -20

# 克隆一个 GitHub 项目（浅克隆，只取最新）
git clone --depth 1 https://github.com/lyracode-app/Lyra-Code.git

# 搜索结果太多？存到文件里再看
rg -n 'error' --glob '*.log' . > /storage/emulated/0/Lyra/rg.out; wc -l /storage/emulated/0/Lyra/rg.out
```

### 7.3 破坏性操作纪律（执行前默念）

1. **确认目标**：删除/覆盖前，先让 AI 显示确切路径，确认没有拼错；
2. **范围最小**：能删一个文件不删整个文件夹，能重命名不删除；
3. **可恢复优先**：先备份（.bak）再动手；
4. **失败先看原因**：命令报错 → 看错误信息 → 调整参数重试，**不要盲目重跑**。

### 7.4 新手 FAQ

**Q：让 AI 跑 `rm -rf` 会怎样？**
A：高危命令会被拦截。但保险起见，你也不该提这种需求——有更安全的替代（先备份再删）。

**Q：命令执行到一半超时了？**
A：命令可能还在后台跑。先让 AI 用只读命令查一下状态（进程在不在、文件生成没），再决定继续等还是重来。

**Q：为什么 AI 说"命令不可用"？**
A：Termux 没装/没授权，或设置里的 Termux 开关没开。回第 1 章 5 节检查。

**Q：我能自己动手跑命令吗？**
A：可以，打开 Termux 手动输入，和 AI 共用同一个环境，互不冲突。
