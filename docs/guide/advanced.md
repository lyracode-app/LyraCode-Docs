# 高级功能

本条目会指导你如何在 Lyra Code 配置高级功能，真正面向 Coding 能力。

## Termux（Coding 核心）

这是全应用 Coding 核心配置。为了保持应用轻量，目前并未选择内置 Linux。

**使用前准备：**

1. 提前下载好 Termux（<https://github.com/termux/termux-app>），并配置好权限。
2. 应用发布网页，具体权限如何配置，在应用的 **Termux 页**已经给出详细的方法，照抄就行。

**使用要求：**

- 只有 Termux 正在运行且权限正常允许，Agent 中的 `run_command` 工具才能正常运行。
- 推荐在使用时将 Termux 设置为**前台小窗运行**，防止系统杀后台。

**能力：**

应用利用 Termux 就可以完成复杂的项目开发与调试功能，在 Termux 里可以自由安装所需要的软件包、运行环境、支持的任意 Linux 发行版。

## WebDAV、文件传输

在**设置页 WebDAV** 设置 WebDAV 服务器，用于保存备份和本地文件，支持绝大部分自建和第三方 WebDAV 服务器。部分网盘工具也具备 WebDAV 功能，例如 **Cloudreve、Nextcloud、123 云盘**等。

文件传输支持 **FTP、SFTP、FTPS** 存储服务器，几乎所有服务器和 PC 设备都支持，对网站运维者很有帮助。

## SSH

你可以在**SSH 配置页**添加远程 SSH 服务器并让 AI 执行命令：

- 支持密码和密钥认证。

::: warning 注意
对强交互型的命令支持不佳，千万不要运行复杂强交互的命令。（你执行了也并不会怎么样……）
:::

## SMTP / IMAP

应用从 **3.5.0 版本**开始支持连接 SMTP 和 IMAP 邮件服务器，你可以让 AI 操作你的邮件，辅助处理。

- **邮件发送确认是强制执行**，不会由于开启无审批模式就会自动同意。你也不希望由于误发送不适合的邮件导致麻烦吧。

::: tip 注意
部分邮件商不允许直接使用密码登录，而是使用**授权码**，且此功能需要额外开启才能在外部应用连接。
:::

## MCP 服务器

你可以在 **MCP 服务器页面**添加本地或者远程的 MCP 服务器：

- 支持 SSE 或 HTTP 连接
- 为应用增加更多 Agent 工具

添加后你可以在 **AI Agent 工具页**查看新增的 MCP 工具，它们带有 **MCP 前缀**，非常好认。

## MCP 服务端

你可以在此处**启用 MCP 服务端**，将应用目前的 Agent 工具暴露出来，提供给本地和网络上其他 MCP 客户端使用。

如果你觉得本应用有原生工具很好用，但是又喜欢在其他 Agent 软件对话和工作，不妨使用本功能将工具提供给对方使用。

## 微型服务器

在工作区启动**本地 HTTP 服务器**：

- 用于调试 html / javascript / css 网站项目。
- 支持局域网访问。
- 支持自定义监听主机、端口、密码认证、绑定域名、HTTPS 证书链/私钥和强制 HTTPS。

::: tip 提示
复杂网站推荐让 AI 在 Termux 中配置环境和服务器启动。
:::

## 系统权限

支持通过以下方式获取系统权限：

- **Root 管理器**：获取设备 Root 权限执行 Root 命令。
- **Shizuku**：获取 adb shell 权限执行 adb 和 shell 命令。

::: danger 高风险操作
此功能风险较高，请仔细核对后允许执行，避免 AI 破坏系统和文件。应用会兜底拦截极高危命令。
:::

**Shizuku 特殊情况：**

有时候 Shizuku 会显示已启动，而且给了应用权限，但是还是无法正常使用。这种情况一般出现在：

- 设备重启之后
- 长期不使用，adb 进程丢失

**解决方案：** 前往 Shizuku 关闭对本应用的授权，重新点击启用，再开启对本应用的授权，重启本应用就可以正常使用 Shizuku 了。

## 子代理编排

子代理允许你设置若干额外的模型，作为**子代理**协助主模型完成任务。

**配置子代理：**

在**设置页**中配置子代理，你可以为每个子代理选择：

- 使用的模型
- 对应的服务商
- 系统提示词（定义子代理的角色与职责）

**在对话中使用：**

配置完成后，在对话页打开**底部动作面板**，即可启用或停用子代理。

**工作方式：**

- 当你执行复杂的复制任务时，主模型可以**为子代理分发任务**。
- 多个子代理可以并行处理不同的子任务，再由主模型汇总结果，辅助更快地完成整体任务。

::: tip 提示
为不同的子代理设置不同的角色与模型，可以让它们各司其职，例如一个子代理负责代码审查，另一个负责文档编写。
:::
