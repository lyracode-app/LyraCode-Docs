# 第 21 章：用量统计、设备诊断与存储——看数据、查设备、清缓存

## 21.1 Token 是什么

Token 是模型处理文本的计量单位，不等于汉字数或单词数。一次请求的消耗不只包含你输入和 AI 正文，还可能包含系统提示词、历史消息、思考、工具定义、文件内容和工具输出。

## 21.2 打开统计页

从侧栏进入 **统计**。可以查看：

- 对话数；
- 消息数；
- 用户输入 Token；
- AI 输出 Token；
- 模型使用分布；
- 日、周、月、年、总计和历史时间段。

页面还提供统计口径说明。先确认选中的日期范围，再比较数字。

## 21.3 统计值怎样计算

Lyra Code 使用离线 Token 估算，不需要把统计数据发给第三方。思考过程、工具上下文、文件读取、命令输出和重复上下文会计入相应估算。

它适合比较趋势，不等同于服务商账单。服务商可能使用不同分词器、缓存计费、图片计费和隐藏输入规则，最终费用以服务商控制台为准。

## 21.4 怎样用统计降低成本

1. 比较相同任务使用不同模型的输入/输出量；
2. 长对话明显膨胀时使用历史压缩；
3. 不要反复读取完整大文件；
4. 命令输出先过滤或保存，再读取关键片段；
5. 简单标题总结使用轻量模型；
6. 只有真正可并行的复杂任务才启用子代理。

## 21.5 手机信息

入口通常在 **设置 → 关于软件 → 手机信息**。可查看厂商、型号、Android 版本、CPU/硬件、ABI、内存、存储、屏幕、网络、蓝牙和电池状态。

这些信息可帮助判断：

- PRoot 是否支持 arm64；
- 存储是否足够；
- 网络与蓝牙状态；
- 屏幕与刷新率能力；
- 某些系统兼容问题。

硬件信息是诊断线索，不是鉴定手机真伪的绝对证据。

## 21.6 硬件检查 Agent

可以让 Agent 读取设备硬件信息后分析，例如：

> 只读取设备硬件信息，解释这台手机能否使用 PRoot Linux，以及内存和可用存储是否适合。不要执行系统命令。

对于电池健康、硬件故障等结论，AI 只能基于可见数据推测，不能替代维修检测。

## 21.7 已安装应用列表

获得相应能力后，Agent 可列出应用名称、包名、版本等信息，用于找包名或排查冲突。它不会因此读取其他 App 内部数据。

## 21.8 缓存与存储

打开 **设置 → 缓存与存储**，页面会扫描：

- 应用总占用；
- 安装包占用；
- 应用数据；
- 系统缓存；
- 可安全清理的缓存目录；
- 持久数据和外部私有目录。

只有标记为可清理的缓存项才提供清理操作。模型配置、对话、备份、Skills 和 PRoot rootfs 等持久数据不应被当作普通缓存删除。

清理缓存前停止正在进行的下载、编辑和服务。清理后首次打开某些页面可能需要重新生成缓存，属于正常现象。

## 21.9 日志

侧栏 **日志** 用于查看部分运行记录；微型服务器还有自己的终端日志页，任务和下载也各自显示结果。排障时先去最接近功能的日志位置：

- 模型错误：对话工具/错误卡片；
- 微型服务器：微型服务器终端日志；
- 定时任务：任务完整结果；
- 下载：下载任务详情；
- 通用执行记录：侧栏日志。

分享日志前删除 API Key、Authorization、邮箱、IP、路径和个人内容。

## 21.10 常见问题

### 统计和服务商账单不一致

这是正常的估算差异。核对时间范围、模型、缓存计费和多模态费用，金额以服务商为准。

### 存储扫描很慢

目录中文件多或 PRoot 环境很大时需要时间。保持页面前台，不要同时进行大量文件操作。

### 清理缓存会删除聊天吗

只使用页面明确标记的可安全清理项，一般不会删除持久对话。重要数据仍应先做备份。
